# Case Study — `schema-validator check-fivem` against the QBCore ecosystem

> 2026-05-02. First real-world dogfood pass of the FiveM resource graph linter.
> Repo state, exact commands, raw output, and findings — verifiable end-to-end.

## Setup

Cloned six unmodified public repos from `qbcore-framework` and `overextended` into a single tree, the way a server owner would have them sit under their `resources/` folder:

```bash
mkdir -p /tmp/qb-tree && cd /tmp/qb-tree
git clone --depth=1 https://github.com/qbcore-framework/qb-core.git
git clone --depth=1 https://github.com/qbcore-framework/qb-target.git
git clone --depth=1 https://github.com/qbcore-framework/qb-spawn.git
git clone --depth=1 https://github.com/qbcore-framework/qb-multicharacter.git
git clone --depth=1 https://github.com/qbcore-framework/PolyZone.git
git clone --depth=1 https://github.com/overextended/oxmysql.git
```

Then ran:

```bash
schema-validator check-fivem /tmp/qb-tree
```

## What this caught

Every issue above is **real configuration debt** in production-grade QBCore code:

### 1. `qb-spawn` references `@qb-core/init.lua` but doesn't declare `qb-core` as a dependency

`qb-spawn`'s `fxmanifest.lua` line:

```lua
shared_scripts {
    '@qb-core/import.lua',
    'config.lua'
}
```

…with no `dependencies { 'qb-core' }`. This works at runtime **because of FiveM's lexicographic load order** — `qb-core` boots before `qb-spawn` because of the alphabetical-by-default startup. Move the resources into a categorisation folder that loads `qb-spawn` before `qb-core`, or rename either folder, and the server fails to start. The dependency is implicit, not declared, and is a real maintenance hazard.

### 2. Multiple resources reference `@qb-apartments` without declaring it

Both `qb-spawn` and `qb-multicharacter` `require` resources from the now-renamed `qb-apartments`. The current upstream is `qb-apartments`, but the assumption that it's loaded is undeclared. If a server owner is using a fork or omits this resource, those scripts break silently.

### 3. `qb-core` declares `oxmysql` as a dep — but `oxmysql` source checkout lacks `fxmanifest.lua`

The `oxmysql` repo from `overextended` ships only TS source. Its `fxmanifest.lua` is generated by `npm run build`. A server owner who clones source instead of using a release artifact (a common mistake) gets a runtime crash because the resource has nothing to load — the linter would catch this before they hit start.

We treat this as a **warning, not an error** — the dep is present in spirit (folder exists), it's just a build-state issue. The message tells the user exactly what to do (`npm run build`).

## Linter improvements made from this dogfood pass

Two changes shipped while running this case study:

1. **Accept plural `games {'gta5'}` as equivalent to singular `game 'gta5'`.**  
   Found in `PolyZone`'s manifest. Both forms are FiveM-valid; the plural is used to declare multi-game support. Original linter false-positive'd as `missing-required-field`. Now silent — correctly accepts.

2. **New issue category: `dependency-no-manifest` (warning).**  
   Distinguishes "dep folder is missing entirely" (`dependency-not-found`, error) from "dep folder exists but has no manifest yet — likely TS-built resource pre-build" (`dependency-no-manifest`, warning). Reduces false-positive errors against modern build-step resources.

## What this is NOT

- A criticism of QBCore. Every modern FiveM resource ecosystem has the same patterns. The ecosystem grew organically over years with implicit conventions; the linter just makes them explicit so they survive future refactors.
- A proof that QBCore servers will break. They run fine today. The linter flags **fragility**, not breakage.

## Why this matters

Bethesda mods have had cross-reference validators (xEdit, TES5Edit) since ~2010. FiveM has had nothing equivalent — server owners hit these dependency-graph footguns one at a time, in production, after a restart. `schema-validator check-fivem` is the missing static type-check for Lua resources.

## How to reproduce

The exact commands above, on any Linux/macOS/Windows machine with `git`, `node 20+`, and Boilergen's schema-validator built. ~30 seconds end-to-end including clones.

## What would harden the linter further (future work)

- Parse `Config.MultiCharacter`, `Config.JobsCreator` etc. constants used as cross-resource API surface, validate they're exported by the right resource.
- SQL migration drift detection: parse `*.sql` files in resources, build a column inventory, validate that Lua `MySQL.query('SELECT col FROM tbl')` references columns that exist.
- `qb-target` zone validation: parse `exports['qb-target']:AddBoxZone(...)` calls, validate the entity model name resolves.

These are tracked in `tools/schema-validator/README.md` roadmap as v0.7+.
